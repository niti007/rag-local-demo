# 00 — Overview: What This Course Teaches

## Concept

**Retrieval-Augmented Generation (RAG)** answers questions by combining two
things that neither a search engine nor a raw LLM does well alone:

1. **Retrieval** — find the small number of passages, out of a large private
   corpus, that are actually relevant to a question.
2. **Generation** — hand those passages to a language model and ask it to
   compose a fluent, *grounded* answer that cites where each claim came from.

The point of RAG is that the LLM never has to "know" your private documents.
It only has to read whatever the retrieval step hands it, in-context, at
answer time. That means:

- You can update the corpus (add a new PDF) without retraining or
  fine-tuning anything.
- The model can say "I don't know" when the corpus doesn't cover a question,
  instead of confidently making something up.
- You can point to the exact chunk of text that backs every sentence of the
  answer.

This project — **Cascade Bank**, a fictional bank invented purely for this
teaching demo — builds a complete, local-first RAG pipeline over synthetic
policy PDFs, SOPs, and CSVs. Every stage of the pipeline is a real,
readable Python module you can run, break, and inspect.

> **Cascade Bank does not exist.** All documents are synthetic (Faker +
> templated text), generated by `src/data_gen/`. See
> [`01-synthetic-data.md`](01-synthetic-data.md).

## The 8-stage pipeline

```

 │ synthetic    │   │ raw text from │   │ token-bounded │   │ local          │
 │ PDFs/SOPs/   │   │ PDFs & CSVs   │   │ splits with   │   │ sentence-      │
 │ CSVs (Faker) │   │ (pypdf/pandas)│   │ overlap       │   │ transformers   │
 └──────────────┘   └───────────────┘   └───────────────┘   └───────┬────────┘
                                                                     │
 ┌──────────────┐   ┌───────────────┐   ┌───────────────┐   ┌───────▼────────┐
 │ 8. UI        │◀──│ 7. GENERATE   │◀──│ 6. RERANK     │◀──│ 5. QDRANT      │
 │ Chainlit chat│   │ OpenRouter    │   │ local cross-  │   │ server (Docker)│
 │ (retrieve/   │   │ (gpt-4o-mini),│   │ encoder       │   │ vector store   │
 │ rerank/answer│   │ cited answer  │   │ re-scores     │   │ (unified       │
 │ panels)      │   │ or fallback   │   │ shortlist     │   │ collection)    │
 └──────────────┘   └───────────────┘   └───────▲───────┘   └───────┬────────┘
                                                 │                   │

                                             query embedding + cosine
                                                 top-k lookup
```

Read left-to-right, top row then bottom row: **generate → extract → chunk →
embed → Qdrant → search → rerank → generate (answer) → UI**. The first four
stages ("ingest-time") run once (or whenever the corpus changes); the last
four ("query-time") run on every user question.

## The local-vs-OpenRouter split, and why

This project deliberately does **not** use OpenRouter (or any hosted API)
for embeddings or reranking — only for the final answer-generation step.

| Stage | Where it runs | Model | Why |
|---|---|---|---|
| Embeddings | **Local** (CPU, sentence-transformers) | `BAAI/bge-small-en-v1.5` (384-dim) | OpenRouter has no embeddings endpoint — it is a chat-completions proxy over hosted LLMs, not an embeddings provider. Even if it did, embedding every chunk of a corpus over a network API is slow and costs money per call; a small local bi-encoder does it in milliseconds on CPU, for free, offline, and deterministically (good for teaching and for the on-disk cache in `src/embed/cache.py`). |
| Reranking | **Local** (CPU, sentence-transformers `CrossEncoder`) | `cross-encoder/ms-marco-MiniLM-L-6-v2` | Cross-encoder rerankers score every (query, passage) pair jointly, which is much more accurate than bi-encoder cosine similarity but too slow to run over an entire corpus. Running it locally over just the retrieved shortlist (`cfg.search.top_k` candidates) is fast and needs no API key at all. |
| Answer generation | **OpenRouter** | `openai/gpt-4o-mini` | This is the one place an actual large language model is required to turn retrieved chunks into fluent prose with citations. OpenRouter gives access to many hosted models behind a single `OPENROUTER_API_KEY` and an OpenAI-compatible API, so the whole demo needs **exactly one** external credential. |

So: **two local models, one API key.** This keeps ingestion (generation +
extraction + chunking + embedding + storage) entirely offline and free to
re-run as many times as you like, and isolates the only paid/networked call
to the single step where it's actually needed — synthesizing the final
answer. If `OPENROUTER_API_KEY` isn't set, everything up through reranking
still works, and the UI/CLI fall back to a "retrieved-context-only" mode
(see [`08-answer-generation.md`](08-answer-generation.md)).

## Quickstart: run the whole thing

From the project root (the folder containing `config.yaml`):

```powershell
# 1. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install dependencies
pip install -r requirements.txt

# 3. Set your OpenRouter key (only needed for the final answer-generation step)
copy .env.example .env
notepad .env      # set OPENROUTER_API_KEY=sk-or-...

# 4. Run the full pipeline: generate corpus -> ingest -> inspect -> project
python scripts/run_full_pipeline.py

# 5. Launch the chat UI
PYTHONPATH=. chainlit run src/ui/app.py
```

`scripts/run_full_pipeline.py` runs, in order: `generate_all()` (writes
synthetic PDFs/SOPs/CSVs to `data/raw/`), `ingest_all(reset=True)`
(chunk → embed → upsert into Qdrant, wiping any existing collection first),
`print_stats()`, and `embedding_projection()` (writes a 2D scatter plot to
`docs/course/embedding_scatter.html` / `.png`). Pass `--skip-gen` to re-run
ingestion against whatever is already in `data/raw/` without regenerating
the corpus.

If you don't have an `OPENROUTER_API_KEY` yet, everything through step 4
still works — the UI and CLI tools fall back to a no-LLM
"retrieved-context-only" mode (see [`08-answer-generation.md`](08-answer-generation.md)).

Every lesson in this course maps directly to real files in this repo — no
